MotoKey Controller — System Design

Generic encrypted rolling-code relay controller. Use cases: e-motorcycle kill switch, deadbolt lock, gate controller. Phase 1 (KeeLoq fob + buzzer) and Phase 2 (LoRa remote access).

1. The Problem

MotoKey is a generic encrypted rolling-code relay controller. The same PCB and firmware serves multiple use cases — the only difference is the enclosure and wiring harness.

E-Motorcycle Kill Switch

E-motos (Sur-Ron, Talaria, Zero, NIU) have no ignition key — they use a simple toggle switch or app. MotoKey intercepts the motor controller enable wire so the bike won't move without the owner's key fob.

Deadbolt / Gate Lock

Same controller drives an electric strike or motorized deadbolt. Relay output replaces the enable wire with the lock's power circuit. Walk-up fob unlock + optional LoRa remote access.

2. Where It Mounts

Installation Location
  • Under the seat — every e-moto has space here, accessible for install, hidden from thieves
  • Zip-tied or velcro-strapped to the frame — no drilling required
  • Near the existing motor controller — short wire run to intercept the enable line
  • Antenna wire routed up toward seat hinge for best RF reception
Critical Design Insight: Intercept the Enable Wire, NOT the Power Wire

E-motos run 48-72V at 40-100A to the motor. You do NOT want a relay switching that. Instead, every motor controller has a low-current enable/key wire (the existing ignition switch). MotoKey's relay (10A @ 5V) switches this enable wire. When the relay is open (armed), the motor controller stays off regardless of the main power switch.

5. How the User Uses It

6. Lock / Unlock State Machine

Fail-Secure Design

Power on → ARMED (relay open, motor disabled). This is the critical safety property. If power is lost, cut, or the controller fails, the relay opens and the bike can't move. A thief cannot bypass MotoKey by cutting its power wire — that just makes the bike more locked.

The ONLY way to enable the relay is: valid KeeLoq rolling code from a paired fob (or LoRaWAN command in Phase 2).

7. Diagnostics — LED + Buzzer

Two LEDs (red + green) visible through the enclosure window and a passive piezo buzzer (BZ1) communicate all states. The buzzer is driven by PWM on PD6 (OC0A) — different tone frequencies distinguish events.

Audible Feedback — Why It Matters

You can't always see the LED. The bike is under a cover, the deadbolt is around a corner, or you're walking away in sunlight. The buzzer gives instant confirmation without looking: one beep = locked, two beeps = unlocked. Same mental model as a car key fob. Total cost: ~$0.30 (passive piezo + 100Ω resistor).

Implementation: BZ1 is a passive piezo buzzer driven via R5 (100Ω current limit) from PD6/OC0A. Timer0 generates PWM at different frequencies: 2.7 kHz for "lock" tone, 4 kHz for "unlock" tone. No amplifier needed — passive piezo at 5V is audible at 3+ meters.

Why LED + Buzzer Is Enough

No screen, no app, no Bluetooth. Two LEDs + one buzzer + one button. A rider parked on the street needs to know exactly two things: "is it armed?" and "did my fob work?" Sound confirms without looking. Everything else is a one-time setup event.

Why IP67 Matters for E-Motos

E-motos are ridden in rain, parked outdoors, and pressure-washed. Under-seat areas get splash, puddle spray, and condensation. IP65 (jet spray) is minimum; IP67 (brief submersion) gives margin for the real world.

9. Phase 1 / Phase 2 Roadmap

Phase 1 KeeLoq Fob + Buzzer
  • SX1278 in ASK mode — demodulates 433 MHz KeeLoq rolling codes from off-the-shelf HCS301 fobs ($3 each)
  • Passive piezo buzzer — single beep (lock), double-beep (unlock), error buzz
  • Two status LEDs — red (armed) + green (unlocked)
  • Learn button — pair up to 4 fobs, 10-sec hold to erase all
  • Fail-secure relay — power-on = armed, relay open
  • No internet required. No gateway. No app.
Phase 2 LoRa Remote Access
  • SX1278 switches to LoRa mode when not listening for fobs — time-shared radio
  • LoRaWAN uplink: lock state, battery voltage, temperature, tamper events → TTN → cloud dashboard
  • LoRaWAN downlink: remote lock/unlock commands from phone via TTN cloud
  • Range: 2-5 km urban, 10+ km line-of-sight (vs 10m for fob)
  • Requires a LoRaWAN gateway ($50-100 or public TTN coverage)
  • AES-128 end-to-end encryption built into LoRaWAN spec
  • Optional 1.54" e-paper display (J5) — shows QR code for Lightning/LNURL payment at laundry machines, vending, or gate access
E-Paper QR Display (J5) — Laundry Payment Flow

The optional 1.54" e-ink display (200x200 pixels, ~$5) connects via the 8-pin J5 header. It shares the SPI bus with the SX1278 radio (separate chip selects). The display draws zero power while showing an image — the QR code persists indefinitely.

How it works: The QR code encodes a static LNURL-pay endpoint (e.g., pay.motokey.io/m/DEVICE_ID). Tenant scans with any Lightning wallet → phone fetches a fresh invoice from your server → pays → server sends LoRaWAN downlink → relay enables machine for one cycle. The QR code on the display never changes — it's written once at firmware flash time.

Pin budget: PC2 (CS), PC3 (DC), PC4 (RST), PC5 (BUSY) — the last four available GPIO on the ATmega328P. SPI bus (MOSI/SCK) shared with SX1278 and ICSP. All 32 pins now assigned.

SX1278: One Radio, Two Modes

The SX1278 ($3) replaces the SYN480R ($0.50) from the original design. It's a multi-mode transceiver that can demodulate ASK (for KeeLoq fobs, 433 MHz) and LoRa (for long-range/LoRaWAN) — but not simultaneously. The firmware time-shares: listen for fobs in ASK mode (default), periodically switch to LoRa mode to check for downlink commands and send telemetry. Fob response latency stays under 100ms.

Same PCB, same headers. Phase 1 firmware only uses ASK mode. Phase 2 firmware adds LoRa time-sharing. No hardware change needed — J4 (SX1278) carries SPI + IRQ + RESET, J5 (e-paper) uses the remaining PC2-5 GPIO. All 32 ATmega328P pins are now assigned.

Battery Backup + USB Charging (Optional)

A MCP73831 single-cell LiPo charge controller (U3, SOT-23-5, $0.40) charges a 3.7V LiPo cell (BT1) from USB Micro-B (J7) at 500mA. A BAT54 Schottky diode (D3) provides automatic power-path switching:

  • 12V present — LDO runs the system at 5V. Schottky is reverse-biased (3.7V < 5V). Battery charges independently from USB.
  • 12V absent — LDO output drops. Battery feeds through Schottky at ~3.4V (3.7V − 0.3V drop). ATmega328P runs fine at 3.3V+ with 8MHz internal oscillator.
  • Low-power mode — Firmware sleeps, wakes on timer/interrupts. Relay won't engage (needs 5V), but LoRa uplinks, sensor reads, and zone monitoring work. Ideal for standalone sensor nodes, tip jars, and water leak detectors.

COGS impact: +$3.70 (charger IC $0.40 + passives $0.80 + LiPo $2.50). Battery option adds value for deployments without permanent 12V power.

10. Mechanical Securing

Anti-Tamper Considerations
  • Hidden installation — under seat, not visible from outside
  • Cutting the MotoKey power wire → relay opens → bike stays disabled (fail-secure)
  • Cutting the relay output wire → motor controller enable line is severed → bike disabled
  • Bypassing by shorting relay output → requires finding the box AND hot-wiring the specific wire — same difficulty as hot-wiring the original ignition
  • Potted PCB → can't probe or reprogram the MCU without destroying the board

10b. Sensors & Zone Inputs

Temperature Sensor (TH1 — NTC Thermistor)

A 10k NTC thermistor on ADC6 measures ambient temperature via voltage divider (R6 10k pullup to +5V). At 25°C the divider output is 2.5V (mid-range ADC). The Steinhart-Hart equation in firmware converts ADC counts to °C.

Use cases: Over-temperature alarm (e-moto battery bay), freeze warning (deadbolt/gate), environmental logging via LoRa telemetry. Phase 2 includes temperature in every uplink packet.

Light Sensor (R8 — LDR Photoresistor)

A photoresistor (LDR) on ADC7 with R7 10k pullup. In darkness (enclosure sealed), LDR resistance is >1MΩ → ADC reads near 5V. If the enclosure is opened, ambient light drops LDR resistance → ADC voltage drops sharply. A firmware threshold triggers a tamper alert.

Use cases: Enclosure tamper detection (someone opened the box), day/night detection for scheduling, light level logging. Combined with zone inputs, this creates a basic intrusion detection system.

Zone Inputs (J6 — 7-pin Header)

Five digital GPIO inputs (PB1, PB2, PD0, PD1, PD7) exposed on the J6 header alongside +5V and GND. Each input uses the ATmega328P's internal pullup resistor — external wiring is simple 2-wire (signal + GND). Connect any NO/NC contact sensor:

  • Reed switches — door/window open/close detection (magnet-based, NO or NC)
  • PIR motion sensors — wired PIR with relay output
  • Water leak sensors — conductive probe, closes circuit when wet
  • Vibration sensors — tilt/shock switches for tamper detection
  • Panic buttons — wired NO pushbutton for manual alarm trigger

Phase 1: Zone state changes trigger buzzer alert pattern. Phase 2: Zone events generate immediate LoRa uplink with zone ID + state + timestamp. Combined with temp/light sensors, this turns the MotoKey controller into a basic security alarm panel.

15. Phase 2 Use Cases

Phase 2 firmware adds LoRa time-sharing to the same PCB. The SX1278 alternates between ASK (fob listening) and LoRa (long-range telemetry + remote commands). A LoRaWAN gateway within range connects the controller to the internet.

E-Moto Remote Kill & Tracking

Remote lock/unlock via phone app through LoRaWAN downlink. Periodic uplink reports GPS (if external module added), battery voltage, temperature, and lock state. Theft alert on tamper (light sensor) or unexpected motion (zone input).

Rental Property Security

Controller as alarm panel: reed switches on doors/windows (zone inputs), light sensor for tamper, temperature for freeze/heat alerts. Zone events trigger immediate LoRa uplink → push notification to landlord. Remote arm/disarm between tenants.

Coin-Op Laundry Payment

E-paper displays a static LNURL QR code. Tenant scans → Lightning payment → server sends LoRa downlink → relay enables machine for one cycle. No coins, no app install, no Bluetooth pairing. Works with any Lightning wallet.

Tip Jar / Donation Box

E-paper QR on a countertop device. Customer scans, pays any amount over Lightning. Display updates with a thank-you message or running total. Zero ongoing cost — LoRa backhaul, no WiFi or cellular needed.

Vehicle / Asset GPS Tracker

Periodic LoRa uplink with location (external GPS module on a zone input or serial), temperature, and motion state. Long battery life at SF12 with one uplink every 15 min. Covers trailers, generators, construction equipment.

Water Leak & Environmental Monitor

Conductive probe on a zone input detects water. NTC thermistor monitors pipe temperature. LoRa uplink on state change — alert before damage. Deploy in basements, under sinks, near water heaters. Battery-powered via USB-charged LiPo — no wiring needed.

Battery mode enables all standalone use cases — water leak, tip jar, GPS tracker. USB recharge via any phone charger. Low-power firmware sleeps between LoRa uplinks, targeting weeks of battery life on a 1000mAh cell at 15-minute telemetry intervals.
